# Naninovel Mobile — Pre-alpha 003

## Scope of this build

This preparation adds the first dedicated launcher flow on top of Winlator 11.2. It is a source build, not an APK, and has not been run on an Android device.

## Implemented in source

- Replaced the app entry screen with a minimal Naninovel-branded launcher using the TSOA executable icon already extracted in Pre-alpha 002.
- On first run, installs the bundled Winlator RootFS into app-private storage, then asks the user to select the complete `game/` folder through Android's Storage Access Framework.
- Copies the full folder into `files/game` using a staging directory and rename-on-success, preserving the Unity file tree and the multi-gigabyte `.assets.resS` data files.
- Performs a free-space preflight with 512 MiB reserve and monitors available storage during large copies; stops the import before storage becomes critically low.
- Validates the Unity game root (`TSOA.exe`, `UnityPlayer.dll`, `GameAssembly.dll`, `baselib.dll`, `TSOA_Data/boot.config`, `resources.assets`, `resources.assets.resS`, `il2cpp_data`, `Plugins`, `StreamingAssets`).
- Creates and persists one dedicated container using the upstream container-pattern asset.
- Configures the container for `native` landscape display sizing, Turnip + GLADIO, DXVK, ALSA and Box64 Stability.
- Maps the app-private game folder as Wine drive `F:` and passes the exact `TSOA.exe` path through the existing `exec_path` launch mechanism.
- Adds `naninovel_mode` to the X Server activity: drawer stays locked, four-finger menu gesture is disabled, Android Back exits the game session and returns to the launcher instead of restarting the upstream Winlator UI.
- Makes Android Back on the launcher close the dedicated app rather than reveal the upstream Winlator container screen.
- Removes legacy broad external-storage permissions; folder access is granted explicitly through the system folder picker.
- Adds a GitHub Actions workflow to build a debug APK in the cloud, useful when developing from Android without a local SDK/NDK setup.

## Important packaging constraint

The approximately 7 GB game folder is not embedded in a single APK. The first-run launcher imports the user's existing game folder from a selected folder. This avoids a multi-gigabyte APK/ZIP64 package and keeps the Winlator runtime APK separate from proprietary game data.

## Graphics assumptions

The initial target is Qualcomm Adreno and the Direct3D 11 path is DXVK -> Vulkan -> Turnip. This is a fixed initial profile, not proof of compatibility on every Adreno generation. The supplied HONOR X8 / Snapdragon 680 / Adreno 610 is the first test device.

The selected `native` resolution is resolved in landscape and dimensions are swapped if Android reports portrait dimensions, preserving the phone's own wide aspect ratio rather than forcing 16:9.

## Test procedure on HONOR X8

1. Install the debug APK generated by CI.
2. Open Naninovel Mobile and allow RootFS preparation to finish.
3. Select the folder that directly contains `TSOA.exe` and `TSOA_Data` (for the screenshot shared, this is the `game/` folder).
4. Keep the app open until import completes; the importer requires the game-folder size plus a 512 MiB safety reserve in internal app storage. The RootFS is prepared before the import begins; keep additional space for container creation and saves.
5. The app creates its dedicated container and starts `TSOA.exe`.
6. Record whether the X Server initializes, whether the game reaches its first screen, whether audio/touch work, and whether Android Back returns to Naninovel Mobile.

## Notes

- Do not remove Vortek, VirGL, Zink, VKD3D or alternate DXVK assets in this pre-alpha. Cleanup remains deferred until runtime works.
- The launcher uses the original Winlator engine/classes rather than a guessed external Intent API.
- The app-private game copy is separate from the APK. Any later bundling proposal must keep the game payload outside a single APK or use a separately delivered asset package.
